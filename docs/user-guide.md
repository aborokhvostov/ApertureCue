# Руководство пользователя ApertureCue 0.1

Это ранняя настольная сборка для macOS 13+. Точное состояние проверок находится в [status.md](status.md). Описанные ниже рабочие операции не означают полного покрытия MadMapper 6.

## Запуск и демонстрационный проект

Из корня исходников выполните `./scripts/build.sh`, затем `open dist/ApertureCue.app`. Приложение стартует с двумя процедурными поверхностями и двумя сохранёнными вариантами геометрии. Для собственного демонстрационного изображения и видео выполните:

```sh
dist/ApertureCue.app/Contents/MacOS/ApertureCue --generate-demo examples/Demo
dist/ApertureCue.app/Contents/MacOS/ApertureCue examples/Demo/Demo.aperturecue.json
```

Генератор создаёт `calibration.png` 960×540, `motion.mov` H.264 640×360, 30 fps, 3 секунды и `Demo.aperturecue.json`. Это собственные тестовые материалы. При повторном запуске генератора существующий `motion.mov` не заменяется; для независимого опыта выберите новую папку.

## Медиа и поверхности

**Import…** или File → Import Media… (`⌘I`) открывает выбор изображений и видео. При импорте источник назначается выбранной поверхности; если поверхности нет, создаётся новая. Для повторного назначения выберите media слева, затем surface и нажмите **Assign to surface**.

**+ Quad**, **Duplicate**, **Delete** изменяют список поверхностей. Список подписан `back → front`: последующие строки рисуются поверх предыдущих. Кнопки со стрелками меняют порядок. Это собственное соглашение ApertureCue; оно отличается от списка слоёв функционального референса.

В режиме **Output geometry** перетаскивайте четыре угла выбранного quad. Вершины не должны пересекаться или схлопываться. **Shift** включает привязку к сетке 5% canvas. В **Input region** отображается исходное медиа и отдельно редактируется его область выборки. Изменение input не меняет output. Геометрия хранится в нормализованных координатах; изменение размера окна не перемещает поверхность в проекте.

**Reset quad / input** сбрасывает текущую сторону. Изменение output corners после создания warp mesh сбрасывает эту сетку; это ограничение текущего редактора. **Create 4 × 4 warp mesh** создаёт регулярную сетку. **Edit mesh points / Edit quad corners** переключает редактируемые handle points. Это регулярная линейная warp-сетка; Bézier mesh остаётся следующим этапом. Узлы текстурного пути редактируются отдельно, как описано ниже.

### Triangle и Ellipse

Кнопки **+ Triangle** / **+ Ellipse** создают поверхности, а **Shape · four-corner frame** меняет форму выбранного слоя с Undo/Redo. Все формы сохраняют четыре ручки перспективной рамки; треугольник задаётся точками `(0.5,0)`, `(1,1)`, `(0,1)` внутри неё, эллипс — вписанной окружностью в local `[0,1]²`. Изменение пропорций рамки даёт эллипс, перспектива и mesh деформируют форму вместе с изображением. Это не режим трёх независимых вершин/UV.

Контур формы и **Edge feather** вычисляются в local области, отдельно от crop и polygon mask источника. Антиалиасинг охватывает примерно один пиксель границы; feather задан в нормализованных local единицах, а не миллиметрах/пикселях проектора. **Input region** всегда показывает полный источник. Пустые углы формы пропускают выбор к нижнему видимому слою; прозрачность пикселей изображения и source mask не меняют геометрические границы выбора. При переходе сцены shape переключается дискретно в середине. `Demo/Shapes.aperturecue.json` — самостоятельный процедурный пример обеих форм.

### Line и Bézier

**+ Line** создаёт открытую текстурную линию; **+ Bézier** — кубическую кривую с двумя узлами. Их форма находится внутри обычной перспективной рамки. В **Edit path points** перетаскивайте узлы, а у Bézier — независимые ручки `i` (incoming) и `o` (outgoing). Перенос узла на canvas сдвигает обе его ручки в мировых координатах. **Edit cage corners**, **Input region** и **Edit mesh points** переключают другие, независимые стороны редактирования. При сложенной warp-сетке обратное редактирование выбирает первый покрывающий треугольник: перекрывающиеся части неоднозначны.

**Path nodes…** открывает точные local координаты узла/касательных. Выберите узел, введите значения и нажмите **Save node**; свойства одного узла сохраняются за раз. **Insert after** делит его следующий сегмент пополам, сохраняя кубическую кривую (у последнего узла открытого пути делится предыдущий сегмент). **Remove node** соединяет соседей с оставшимися ручками. Минимум два узла для открытого пути, три для **Closed path**, максимум 32. Замыкание, ширина, вставка, удаление и перетаскивание поддерживают Undo/Redo. Невалидная форма или исчерпанный бюджет точности отклоняются целиком. Переключение Line/Bézier сохраняет узлы и касательные; Line временно игнорирует касательные.

**Stroke width** — полная толщина в долях высоты local рамки при метрике 16:9; численно разрешены 0.001…1. Группа, перспектива и mesh деформируют полосу вместе с рамкой, поэтому это не постоянная ширина в пикселях проектора. Точки и ручки лежат в local `[0,1]²`; полоса, круглые концы и круглые стыки обрезаются границей рамки. Оставляйте запас вокруг пути, если нужны целые концы.

Текстура растягивается один раз вдоль суммарной длины пути; поперечная координата идёт от одной стороны к другой. **Input region** задаёт независимый crop этой текстуры, а polygon mask ограничивает получившиеся source UV. При пересечениях выбирается ближайший сегмент, при точном равенстве — первый. Alpha применяется один раз к объединению полос; UV могут иметь шов на пересечениях/резких поворотах и в месте замыкания. **Edge feather** смягчает край полосы в local единицах.

Кубические сегменты адаптивно разбиваются с local допуском 0.0005, максимум 256 линейных сегментов и глубина 10. Это не гарантия ошибки менее пикселя после сильной перспективы/увеличения. Готовые сегменты кешируются до изменения пути; стоимость GPU зависит от их количества. Свободное рисование мышью, выбор иных caps/joins, filled FreeDraw shapes и Bézier mesh/masks пока не реализованы. `Demo/Strokes.aperturecue.json` показывает собственные line/curve примеры. В сценах совместимые пути интерполируются по точкам/касательным/ширине; несовместимые или схлопывающиеся пути переключаются в середине перехода.

## Цвет, маски и группы

Inspector содержит opacity, brightness, gamma, RGB multiplier и режимы normal/add/multiply/screen. **Generator / fallback** выбирает checker, gradient, solid или grid и снимает назначение медиа. Если назначенный ресурс не загрузился, procedural fallback позволяет продолжить настройку; ошибка отображается в нижней строке.

**Add polygon mask** создаёт редактируемую четырёхточечную внутреннюю маску в координатах источника. **Edit polygon mask** включает её handles; **Remove mask** удаляет. Это одна polygon mask на поверхность; Bézier, несколько масок, holes и глобальные mask surfaces ещё не равнозначно реализованы. **Edge feather** смягчает край поверхности; это не автоматическая калибровка seam двух реальных проекторов.

### Иерархические группы

В **Parent group** выберите существующую группу или Root. Назначение сохраняет мировую геометрию output/mesh; input и source mask остаются прежними. Прозрачность и видимость начинают наследоваться от нового родителя.

**Groups…** / **Group controls…** открывает редактор групп. Выберите **New group**, задайте имя и Parent, opacity 0…1 и видимость. Чтобы включить выбранную поверхность в новую группу, отметьте **Assign selected surface**, затем **Save group**. Для существующей группы сохранение нового Parent сохраняет мировую геометрию всего поддерева. Циклы запрещены. Меню показывает путь и часть UUID, поэтому имя не служит идентификатором.

Для выбранной группы нажмите **Transform…**. Задайте перенос в нормализованных координатах canvas, ненулевой Scale X/Y и угол по часовой стрелке. Отрицательный масштаб отражает. Pivot задан в мировых координатах; по умолчанию это центр рамок/mesh всех текущих потомков. Порядок: scale → rotation → translation. Угол учитывает пропорции редакторского canvas 16:9; другой aspect выходного дисплея меняет его видимое направление. Каждый Apply — относительная операция с единым Undo/Redo, локальные точки потомков сохраняются. Вложенные rotation/nonuniform scale могут давать shear, который сохраняется точно в affine-матрице.

**Toggle entire group** меняет собственную видимость группы, сохраняя индивидуальные enabled-флаги поверхностей. Opacity перемножается по предкам после вычисления surface automation. Композиция остаётся в исходном плоском порядке слоёв: opacity применяется к каждому потомку, отдельного группового render buffer нет. Групповые perspective, masks, FX и automation пока не реализованы.

**Dissolve** удаляет определение группы, переносит прямых потомков к её родителю и запекает её affine/opacity/visibility в их состояние. Поверхности, media и ссылки в сценах сохраняются; Undo возвращает всю иерархию. Если opacity группы не равен 1 и на прямом surface target есть opacity track, операция отклоняется: иначе track перекрыл бы запечённый множитель. Удалите соответствующий track или осознанно измените group opacity перед Dissolve.

Сцены сохраняют surface membership/локальную геометрию, но используют **текущие общие определения групп**. Поза группы не входит в surface snapshot. При переходе между разными parent frames membership/output/mesh переключаются вместе в середине перехода; source crop и совместимые числовые параметры могут интерполироваться. Редактирование или Undo во время перехода фиксирует промежуточное состояние как отменяемую команду, включая нажатие ручки без перемещения.

`Demo/Groups.aperturecue.json` — собственный процедурный пример вложенной группы с перспективными примитивами.


## Статический импорт OBJ

File → **Import projected OBJ…** читает polygonal Wavefront OBJ и предлагает camera Z и vertical FOV. Камера смотрит на origin; видимый результат запекается в редактируемые 2D patches, по три quad на каждый triangle. Выбранное media назначается импортированным patches, а OBJ texture V переводится из нижнего левого начала в верхнее левое.

Импорт поддерживает positive/negative indices и planar polygons, но не загружает MTL, внешние textures или исходную 3D-сцену. Чтение/разбор/проекция выполняются в фоне; результат не добавляется в другой документ, если во время работы был выполнен New/Open. UV-degenerate и неподдерживаемая геометрия отклоняются с диагностикой. Static projection ограничена 1365 triangles; ввод — 16 MiB. Triangles сортируются по средней глубине; пересечения не разрешаются depth buffer. Triangle, пересекающий near/far clipping plane, пропускается целиком. Это полезный static mapping path, но не полноценный 3D renderer, calibration или scanner.

## Воспроизведение

**Play/Pause**, **Stop** и slider управляют импортированными видео. Stop ставит на паузу и переводит к началу. Seek в pause должен обновлять кадр, сохраняя pause. В media inspector выбранного видео доступны **Loop ON/OFF**, volume и **Relink media…**. Текущая transport bar общая для media pool; отдельная полнофункциональная плеерная панель на каждый clip ещё не реализована.

Поддержку конкретного файла определяет AVFoundation установленной macOS. Наличие расширения `.mkv`, `.avi` или `.webm` в классификаторе не гарантирует decoder: при ошибке будет показана диагностика. Проверенный тестовый codec/container должен быть указан в status. AVPlayer воспроизводит встроенное аудио через системный вывод; advanced multichannel routing и frame sync нескольких плееров пока не подтверждены.

**Camera…** запрашивает доступ к камере только по действию пользователя и предлагает доступные устройства. Источник назначается выбранной поверхности. Capture backend сохраняет последний кадр, пропускает опоздавшие и выводит диагностику недоступного устройства. Работа без подключённой камеры и сама реализация adapter не подтверждают capture на конкретной модели; доступность/разрешение/отключение проверяются отдельно. Camera source остаётся live при pause movie transport.

## Монтаж источников (alpha 9, schema 7)

Импортируйте изображения и видео через **Import…**. В левой библиотеке нажмите **Montage sources…**, затем **New montage**. Задайте **Name**, **Duration s**, **Loop montage** и поведение пустого участка **Black / Skip**; нажмите **Create montage**. Монтаж появляется в общей библиотеке как назначаемый источник.

Выберите **New clip**, исходный файл в **Source asset**, **Start s** и **Duration s**. Для видео задайте **Video In s / Out s**, **Rate** (0.25…4) и при необходимости **Loop trimmed video**, затем **Add clip**. Изображению нужны только Start/Duration. Нажатие блока на полосе или строки таблицы выбирает клип; время редактируется числовыми полями и **Save clip**. **Delete clip** удаляет выбранный клип. Перекрытия отклоняются; следующий клип может начинаться точно в конце предыдущего. Для видео без clip loop длительность клипа не может превышать `(Out−In)/Rate`.

Изменения свойств монтажа сохраняет **Save montage properties**, правки клипа — **Save clip**. Несохранённые поля остаются draft при обычном обновлении окна. Каждая успешная операция имеет одну команду Undo/Redo. **Seek clip start** переводит общее время шоу к началу выбранного клипа; Play/Pause/Stop и основной slider управляют монтажами вместе с parameter timeline. Длительность графа в **Timeline…** определяет конец самого шоу; длительность монтажа задаёт его собственный конец/цикл.

Выберите поверхность в основном окне и нажмите **Assign montage to selected surface**. Также можно выбрать монтаж в общей библиотеке и нажать **Assign to surface**. Поверхности с одним montage UUID показывают один принятый кадр; разные монтажи одного видео имеют независимые позиции. **Black** выдаёт чёрный источник с обычными opacity/blend поверхности; **Skip** исключает её из композиции и показывает нижние слои. Загрузка, ошибка и отсутствие подходящего кадра используют тот же режим с диагностикой, без подстановки checker. Поворот из video metadata учитывается при чтении texture; surface input/mask остаются в координатах повёрнутого изображения.

Клипы монтажа воспроизводятся без звука. Обычный видеоисточник звучит только при прямом назначении на текущую поверхность; opacity/visibility/routing не отключают его звук. Монтаж не меняет volume или позицию такого обычного источника. Одновременно допускаются восемь активных видеомонтажей; девятый показывает выбранный gap и диагностику. Приоритет определяется UUID. Reverse, crossfade/перекрытия, аудиомонтаж, камеры/вложенные монтажи и запись клипов пока отсутствуют.

Сцены сохраняют UUID назначения, а определения монтажей общие для проекта. **Delete montage** очищает его назначения в текущих поверхностях и сохранённых сценах; Undo восстанавливает всё вместе. Save/Open/Recovery/Collect сохраняют определения и ссылки. `Demo/Montage.aperturecue.json` — собственный пример с изображением, видео, Black/Skip, trim/rate/loop. Schema 7 требует новый reader; alpha 1…8 такие проекты отклоняют. Сохраняйте отдельную копию для старой сборки.

## Выход на дисплей

Нажмите **Outputs…**, выберите экран, затем **Open fullscreen** или **Open preview window**. Это отдельное окно с чистой композицией, без handles редактора. **Escape** закрывает output. **Close outputs** закрывает все output windows. **Blackout** делает output чёрным, оставляя редактор доступным для настройки.

В inspector поверхности можно выбрать **All outputs** либо конкретное назначение. Несколько отдельных окон разделяют media textures и имеют свои render targets. Наличие двух окон на одном экране не считается проверкой двух физических проекторов.

Текущие назначения используют индекс экрана; после изменения конфигурации дисплеев повторно откройте Outputs и проверьте назначение. Сохранённые width/height конфигурации не являются отдельным редактором режимов экрана. Не заявляется автоматическое восстановление при hotplug.

## Снимки и управление шоу

В строке **SCENES** кнопка **Capture** сохраняет полный снимок текущих поверхностей с переходом 1 секунда; выберите его и нажмите **GO**. **Scenes…** открывает редактор полных снимков и selective cues. Оба режима сохраняют только surface state: определения групп, assets, fixtures, output configuration, timeline и transport не входят в снимок. Это более узкая область, чем полный проект Scene в документации референса.

### Создание и изменение Cue

Нажмите **New draft**, задайте **Name**, **Transition s** (0…86400) и **Follow s** (пусто — без продолжения; иначе 0…86400 секунд после конца перехода). Выберите поверхность в **SURFACE FIELDS**, отметьте нужные поля и повторите для других поверхностей. **All fields on surface**, **Clear surface** и **Clear all fields** меняют draft. **Capture selective** создаёт новый Cue с текущими значениями отмеченных полей; нужен хотя бы один target и одно поле. **Capture full** всегда создаёт новый снимок всех текущих поверхностей и их порядка.

У сохранённого Cue scope фиксирован. Для другого scope создайте новый Capture. **Save cue properties / fields** сохраняет имя, timing и выбор полей, оставляя захваченные значения прежними. Включение другого поля уже сохранённой поверхности использует его значение из сохранённого snapshot; Save не читает текущий inspector. При снятии всех полей поверхность исключается из этого Cue. Строки сохранённого Cue ограничены его snapshot: для других текущих поверхностей используйте **New draft**. **Recapture values** явно заменяет захваченные значения текущими для выбранных targets/полей, сохраняя имя и timing. Если изменены имя или timing, сначала сохраните их отдельной кнопкой. **Stored snapshot** и **Current surface** помогают сравнить значения; длинный текст доступен в tooltip. **GO selected** вызывает сохранённый Cue и его сохранённую маску, а не несохранённый draft.

### Поля selective Cue

Каждый target привязан по UUID. Поля ниже — атомарные единицы: связанные payload/селектор сохраняются вместе.

| Поле | Что восстанавливает |
|---|---|
| Opacity | Собственную прозрачность поверхности |
| Brightness | Яркость |
| Gamma | Гамму |
| RGB color | Все три RGB-множителя |
| Feather | Local edge feather |
| Blend mode | Режим композиции |
| Visibility | Собственный enabled-флаг |
| Media / generator | Media UUID и procedural fallback selector вместе |
| Input UV | Четыре input-вершины |
| Output / mesh / parent | Output-рамку, mesh vertices/dimensions и group UUID вместе |
| Shape / stroke | Тип формы и весь payload пути вместе |
| Source UV mask | Полигон источника |
| Output routing | Output UUID либо All outputs |

Selective recall сохраняет текущие имена/UUID, порядок слоёв, новые и невыбранные поверхности, а также все исключённые поля. Удалённый target пропускается с предупреждением; Cue не создаёт его заново. Capture/Recapture требует текущих targets. Неиспользуемые resource references в исключённых полях могут оставаться dormant snapshot data; при включении такого поля его ссылки должны снова быть действительны. Невалидное объединение выбранных и текущих полей отклоняется целиком.

Выбранные числовые поля интерполируются линейно. Visibility, blend/source/routing и несовместимые геометрические/shape payload переключаются в середине; visibility-only Cue не меняет opacity. Input/output quads и совместимые пути интерполируются, если промежуточная геометрия допустима; при схлопывании используется соответствующее допустимое endpoint-состояние. Разные parent frames переключаются вместе с output/mesh. Нулевая длительность применяет конечные значения при обработке recall. Новая команда GO начинает переход от фактического текущего состояния. Редактирование и Undo прерывают fade, сохраняя промежуточное изменение в истории.

Full recall сохраняет прежнее поведение surface snapshot: восстанавливает сохранённые поля и порядок, скрывает более поздние поверхности, сохраняя их определения и automation bindings. Оба режима используют текущие общие определения групп; pose/opacity/visibility группы не захватываются. Dissolve запекает поддерживаемые изменения в текущие слои и применимые Cue fields; неоднозначные изменения appearance или конфликт с opacity automation отклоняются с пояснением.

Recall сам по себе не останавливает и не перематывает media/show clocks. Fades идут по host clock даже при Pause параметрического timeline. Активная timeline automation продолжает перекрывать соответствующие базовые поля Cue; её Pause/loop/seek/end остаются отдельными transport-событиями. Это не frame lock между декодерами. Undo возвращает сохранённое состояние документа до GO. Delete удаляет связанные Scene markers и tracks, потерявшие последний target в текущих поверхностях или оставшихся full snapshots.

Проект сохраняется в schema 7: старые версии 0…5 мигрируют как full surface snapshots; v6 сохраняет selective bindings. Старые binaries, не поддерживающие schema 7, отклонят такой проект; сохраняйте отдельную копию. Cue-owned timelines, quantized launch и calendar scheduler остаются следующими этапами. Журнал ручных проверок selective workflow: [checklist](verification/selective-workflow.md).

### Графический Parameter Timeline

**Timeline…** открывает отдельное окно дорожек, графика и master show transport. Дорожка привязывается к существующей surface и одному из шести параметров: opacity, brightness, gamma, red, green, blue. Выберите Surface/Parameter → **Add track**. Один параметр одной surface имеет одну дорожку; повторное добавление выбирает существующую. Список включает отключённые и временно отсутствующие в текущей сцене targets. **Disable/Enable track** возвращает/включает override базового параметра; **Delete track** поддерживает Undo/Redo.

Выберите дорожку. Double-click графика добавляет ключ; drag ромба меняет time/value одним Undo-командой после отпускания мыши. **Time s**, **Value** и **Save key** задают точные значения. **Delete key** удаляет выбранный ключ; последний ключ удаляется вместе с дорожкой. Времена строго возрастают, не совпадают и лежат внутри Duration; opacity 0…1, gamma 0.01…10, остальные 0…16. Невалидная операция отклоняется целиком. **View/Fit/＋/−** меняют видимый диапазон времени; остальные параметры, кроме opacity, имеют автоматически подобранный диапазон значений.

Interpolation относится к сегменту **после** выбранного ключа: **Hold** удерживает значение до следующего ключа, **Linear** даёт прямую, **Bezier** использует normalized C1/C2. Оранжевые ручки редактируются на графике или численно. Control x/y лежат в 0…1, C1.x ≤ C2.x: временная кривая остаётся монотонной, а значение не выходит за диапазон концов. На flat сегменте касательные не меняют постоянное значение. Значение в точном времени ключа равно этому ключу. За крайними ключами удерживается крайнее значение. Auto Curve ещё не добавлен; запись inspector input описана ниже.

**Play/Pause/Stop**, числовой **Seek** и drag линейки управляют собственным show clock; загруженное видео для этого не требуется. Нижняя панель основного редактора и OSC/MIDI transport управляют теми же часами. **Duration / graph end** задаёт горизонт ключей/маркеров. **Stop at duration** включён в новых проектах: play останавливается в конце; повторный Play начинает с начала. При выключенном Stop время может продолжаться за графиком (до 365 суток), а последние значения ключей удерживаются; typed Seek также разрешён за горизонтом. Проекты v0–v4 мигрируют в этот continue mode, чтобы прежние длинные/looping видео не обрывались через 10 секунд. В новых проектах исходный горизонт — 10 секунд. Установите нужную Duration явно; её сокращение не удаляет находящиеся дальше ключи/маркеры, а отклоняется.

**Loop range** повторяет [Start,End) с сохранением остатка времени при переходе границы; loop имеет приоритет над Stop at duration. При смене позиции/loop/конце master синхронизирует media transport; каждый movie затем применяет собственный loop/clamp по длительности источника. Это не frame lock между декодерами. Вычисление параметров и доставка маркеров выполняются timer tick около 30 Hz с monotonic host time; графическое окно отображает тот же playhead. Seek не генерирует marker events.

**Add marker at playhead** добавляет **Pause** или **Recall scene**. Маркеры должны иметь разные положительные времена внутри Duration; для добавления сначала перейдите к нужному времени. Pause останавливает часы точно на marker time; следующий Play продолжает без повторной остановки на нём. Recall scene вызывает существующую surface scene. Marker срабатывает при естественном проходе `(previous,current]`; seek/попадание ровно в marker time не запускает его. Marker в Loop End проходит перед wrap; marker в Loop Start может пройти в начальном preroll, но не запускается повторно от одного приземления при wrap. **Seek marker** только перемещает playhead. Удаление сцены удаляет её marker references одной Undo-командой.

При длинной задержке обрабатывается не более 256 событий/переходов loop за tick; excess cue events пропускаются с видимой диагностикой, однако первая Pause сохраняется. Изменение дорожек/настроек сохраняет уже естественно пройденные events для однократной доставки; Stop/Seek очищают очередь. Существующие scene fades используют собственный host clock и могут продолжаться, когда parameter timeline поставлен на Pause. Совместная графическая audio/MIDI/OSC montage, внешние clock/timecode, Conductor banks и schedule остаются следующими областями реализации. `Demo/Timeline.aperturecue.json` — собственный параметрический пример.

### Запись scalar automation из inspector

Сначала создайте нужную дорожку через **Add track**. Выберите её и нажмите **Arm selected**; можно подготовить несколько дорожек. Arm разрешён только enabled track текущей поверхности: dormant target из full snapshot для записи не подходит. **Disarm selected** и **Disarm all** снимают подготовку. Arm и режим записи существуют только в текущем сеансе, сами не меняют документ и не сохраняются в JSON. New/Open очищает Arm; удалённые, отключённые дорожки и отсутствующие текущие targets исключаются из него.

Нажмите **Play** внутри **Duration / graph end**, затем **Record input**. В основном inspector двигайте Opacity, Brightness, Gamma, Red, Green или Blue выбранной поверхности. Записывается только её соответствующая enabled/armed дорожка; новые tracks автоматически не создаются. В режиме записи эти slider показывают вычисленное текущее значение и полный допустимый диапазон параметра. Другие sliders и обычные правки документа завершают режим записи перед своей операцией. Это запись изменений этих шести inspector controls: таймер, OSC/MIDI, камера, media/audio и montage не записываются.

Один жест начинается с вычисленного значения дорожки в момент нажатия. Continuous изменения создают linear keys во времени show clock; при обычном отпускании последний принятый value удерживается до момента отпускания. После отпускания режим остаётся включённым для следующего жеста. Каждый изменённый жест — одна Undo-команда, а не вся сессия Record input. Нажатие без изменения value не создаёт команду. Принятые keys сразу входят в документ: они видимы сохранению/recovery даже до завершения жеста. Текущий записываемый параметр применяется к output немедленно; изменение базового surface value для этого не требуется.

Запись заменяет старые keys внутри включённого диапазона `[начало жеста, последний принятый sample]`. Keys снаружи сохраняют свои time/value/interpolation/handles; соседние сегменты могут изменить кривую из-за новых соседей. Записанный участок линейный, его затем можно редактировать обычными средствами графика. Времена одного жеста не убывают; совпавшее время заменяется последним value. Лимиты: до 4096 samples одного жеста и 4096 keys одной дорожки, до 65536 keys проекта. Невалидный sample или превышение бюджета останавливает запись атомарно, сохраняя ранее принятый участок.

**Stop recording**, Pause/Stop/Seek, loop wrap, Scene GO, конец graph duration и редактирование документа завершают режим. При таком прерывании сохраняется только последний принятый участок; искусственный endpoint в момент остановки не добавляется. Запоздалые события старого gesture после прерывания не превращаются в новую правку поверхности. Arm можно оставить для следующего запуска Record input. Старт записи фиксирует активный scene fade; изменение Arm также завершает запись. Save/Undo/Redo завершают текущий жест перед своей операцией.

Запись не перематывает media и не перезапускает show clock. Изменение только keys и Undo/Redo keys сохраняют текущую позицию и playback; реальные Pause/Seek/loop/end выполняют собственные transport-действия. Это не синхронизация декодеров по кадрам. Сама запись создаёт обычные keys ранее введённого формата. Текущий writer сохраняет весь документ как schema 7; для его открытия нужна новая сборка. Arm/режим записи не сохраняются. Наличие описанного workflow не заменяет отдельные автоматические и ручные результаты в status и verification.

## LED mapping и симулятор

**LED…** добавляет линейную fixture по количеству pixels, universe, начальному DMX address и двум нормализованным точкам композиции. Выберите RGB, GRB или RGBW. **Add fixture + simulate** сохраняет layout в проекте и открывает симулятор, не включая отправку в сеть. Адреса каналов начинаются с 1; universe передаётся на провод без автоматического смещения. Fixture не переносится через границу 512 и не перекрывает занятые каналы. Поэтому для RGB при address 1 доступно до 170 pixels, для RGBW — до 128.

Sampling берётся из полной output composition, уменьшенной до 320×180, nearest pixel, с частотой не выше 30 Hz. При занятости GPU/sender кадры пропускаются вместо накопления очереди. Это не фильтрация по площади fixture и не физическая калибровка LED. Симулятор показывает первые raw RGB channel triplets universes; он не декодирует обратно произвольный GRB/RGBW профиль в реальные цвета приборов.

Для отправки задайте числовой IPv4 destination, выберите Art-Net или sACN и нажмите **Start network output**. Порты: Art-Net source/destination 6454, sACN destination 5568. По умолчанию target `127.0.0.1`; отправка включается только явно. При смене target/protocol сначала завершается прежний output, затем применяются новые проверенные settings. **Stop output** останавливает sampling и передаёт нулевые ArtDmx levels либо обычный zero-valued sACN data packet, за которым следуют три packets с Stream Terminated. Это разные действия: receiver игнорирует channel values в terminated packet. **Clear fixtures** сначала останавливает output, затем удаляет layout. Runtime target/protocol не являются сохранёнными полями проекта.

Quit ставит media на паузу, останавливает controls и дожидается очереди lighting Stop с ограничением около одной секунды. Это попытка корректного завершения локальной отправки, а не подтверждение, что UDP packet получен реальным node.

Этот этап поддерживает простые strips и UDP data packets. Полный fixture-definition editor, 16-bit channels, moving lights, protocol discovery/sync, USB-DMX и recorder ещё не закончены. Физическое поведение реального node при blackout/termination требует отдельной проверки. Симулятор и localhost loopback не дают аппаратной совместимости или полной protocol conformance; OEM registration для Art-Net остаётся незавершённой.

## Сохранение, история и экспорт

File > Save (`Cmd-S`) and Save As (`Cmd-Shift-S`) write the own `.aperturecue.json`; Open (`Cmd-O`) reloads it. The current JSON schema is version 7. v0/v1 migrate to quad; v2 retains triangle/ellipse; legacy v0...v2 group labels become UUID groups. v3 stores groups, v4 paths, v5 timeline easing/settings/markers, v6 explicit full/selective cue scope and bindings. Pre-v4 stroke extensions are cleared; v0...v5 cues migrate to full snapshots. v7 adds required montage definitions and extends surface source references; earlier versions discard undefined montage extensions. Saving upgrades to v7. Alpha 1...8 reject schema 7, so keep an older document copy for downgrade. Media paths are relative on disk and absolute in memory.

File → **Collect portable project…** создаёт переносимую копию в новой, ещё не существующей папке. Внутри находятся `project.aperturecue.json` и `media/<asset UUID>.<extension>`. Такое именование разделяет одноимённые источники. Приложение копирует обычные media files, проверяет созданный проект и относительные ссылки, затем публикует готовую папку одним переименованием. Missing media, неподходящий source или ошибка копирования отменяют операцию; исходный проект и выбранная папка назначения не перезаписываются.

Collect работает в фоне со снимком текущего проекта. Открытый документ не переключается на копию; более поздние правки не входят в уже начатый сбор. Live camera IDs сохраняются как ссылки на устройства и на другом компьютере могут быть недоступны. Для переноса откройте `project.aperturecue.json` из собранной папки и перемещайте её целиком.

Undo (`⌘Z`) и Redo (`⇧⌘Z`) работают с правками документа. Drag записывается одной операцией. История ограничена 100 снимками, очищается при New/Open и не сериализуется между запусками. Действия внешних устройств и текущее время плеера не являются document undo.

Для изменённого проекта с уже выбранным именем каждые примерно 10 секунд записывается отдельный recovery file `.<project filename>.recovery`. Успешное ручное Save удаляет его. При открытии проекта приложение предлагает восстановление, если recovery найден. Восстановление после реального принудительного завершения должно быть отдельно проверено в status; внешний или оставшийся recovery file не имеет автоматического timestamp freshness filter.

File → Export PNG… (`⌘E`) сохраняет композицию кадра 1920×1080 без handles. Это still export, а не экспорт timeline/movie или standalone show.

## Диагностика

Нижняя строка показывает renderer FPS, время CPU encode, GPU command time, skipped submissions и сообщения media errors. Эти числа не являются процентом загрузки CPU/GPU или точным счётчиком dropped video frames.

Команды диагностики из корня проекта:

```sh
dist/ApertureCue.app/Contents/MacOS/ApertureCue --self-test
dist/ApertureCue.app/Contents/MacOS/ApertureCue --protocol-loopback
dist/ApertureCue.app/Contents/MacOS/ApertureCue --lighting-test
dist/ApertureCue.app/Contents/MacOS/ApertureCue --benchmark
```

`--self-test` создаёт `artifacts/local/self-test.json`: production Metal и короткий собственный H.264 clip. `--protocol-loopback` проверяет локальную UDP доставку OSC и MIDI parser. `--lighting-test` создаёт `artifacts/local/lighting-test.json`: полный GPU → sampling → production sender → настоящий localhost UDP → decoder, включая color order, automation, routing, blackout и simulation без network. `--benchmark` создаёт `artifacts/local/live-benchmark.json` с короткой серией visible drawable submissions.

Эти локальные серии уже выполнялись успешно в текущем окружении; точные counts/revision/date приведены в [status.md](status.md), а сохранённые отчёты — в [verification](verification). Ни один короткий тест не подтверждает длительный show, оптическую частоту проектора, внешний дисплей, физическую fixture или захват конкретной камеры. В benchmark нет video decoding.
