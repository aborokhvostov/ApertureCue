The end goal remains the complete independently authored projection/video/light/show application described by the [feature matrix](feature-matrix.md). The initial working path is a foundation, not a reduction of that goal. A stage is complete only when its behavior gates pass and the evidence is recorded in [status.md](status.md). Hardware limits hold the corresponding H gate open; simulator, software and portability work can continue.

## Evidence and release gates

Every implementation status needs source and a behavior test/report. A visible button, buildable SDK wrapper or architecture paragraph does not make a function implemented. Every release must list the commit, platform/CPU/GPU, codec, resolution, number of surfaces/outputs, test duration, failures and unmeasured metrics. No “full analogue,” 4K/60, device compatibility or cross-platform desktop claim precedes its corresponding test matrix.

Before publishing a binary: scan tracked content for secrets and foreign/proprietary assets, include matching source/build scripts and license notices, verify archive execution and document signing/notarization status. Before calling CI green: inspect the actual remote run for the published revision. The user-authorized public repository may host checked stages while the larger roadmap remains open.
