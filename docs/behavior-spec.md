# Спецификация поведения самостоятельного приложения

Версия спецификации 0.1, 25.10.2026. Это **собственные проверяемые требования**, основанные на сценариях каталога; документ не описывает неизвестную внутреннюю реализацию MadMapper. Источники и документированные отличия v6 находятся в [research.md](research.md), ID требований — в [feature-matrix.md](feature-matrix.md).

## Координаты и проективная геометрия

Output point и UV хранятся в нормализованных координатах соответствующего output canvas и собственного media source. Output configuration хранит логический размер. Порядок углов: верхний левый, верхний правый, нижний правый, нижний левый. UI может отображать числа в пикселях; изменение размера окна редактора не меняет документ. Retina scale применяется только на границе view/render target.

Для G03 вычисляется homography H, связывающая источник с output: `p' ~ H p`. Перспективное деление выполняется для каждого фрагмента или эквивалентным корректным интерполятором; аффинное текстурирование двух треугольников не проходит приёмку. Независимый контрольный расчёт сравнивает углы, середины и внутреннюю сетку. Допуск координат для двойной точности в unit tests — 1e-6 при умеренном диапазоне координат; pixel golden tests имеют отдельно указанный допуск ресэмплинга.

Выпуклый невырожденный quad разрешён в первом этапе. Нулевая площадь, нечисловое значение, пересечение рёбер и сингулярная матрица дают диагностику, сохраняют последний корректный кадр/документ и не доходят до деления на ноль. Поддержку вогнутых или пересечённых поверхностей можно добавить только с отдельной семантикой tessellation; молчаливое неопределённое поведение недопустимо.

G02: изменение input crop не меняет output vertices. Изменение output не меняет UV. Flip — явное преобразование UV. Если введён mesh link G13, его состояние хранится в проекте; исходное независимое поведение остаётся доступным.

G11/G12: ячейки mesh разделяют общие вершины, чтобы исключить щели. Геометрия и UV отделены. Подразделение сохраняет вид при отсутствии новых деформаций. Foldover либо запрещается с диагностикой, либо имеет документированную сортировку. Bézier precision ограничивается бюджетом tessellation, а не бесконечным накоплением полигонов.

## Примитивы в перспективной рамке

Schema 2 определяет `shape`: `quad`, `triangle`, `ellipse`; неизвестные значения отклоняются. v0/v1 мигрируют к quad. Все формы сохраняют независимые input/output quads. Local треугольник имеет вершины `(0.5,0),(1,1),(0,1)`, ellipse — центр `(0.5,0.5)`, радиус `0.5`. Форма вычисляется после обратного projective/mesh mapping, до пересечения с source-UV mask. Crop не изменяет геометрическое покрытие формы. Feather — smoothstep signed distance в local единицах; triangle использует минимум расстояний к трём поддерживающим прямым, ellipse — радиальное расстояние. Quad сохраняет прежнее покрытие. Новые формы используют примерно однопиксельный derivative AA. При scene interpolation форма переключается в `t=0.5`.

При выборе слоя пустые углы triangle/ellipse не перекрывают нижний видимый слой. Mesh hit test перебирает обе triangles каждой cell, включая folded overlap; маски источника и feather не являются геометрическими границами выбора. Контур редактора — ограниченная дискретизация, рендер ellipse — аналитическое покрытие. В режиме Input показывается полный прямоугольный источник независимо от shape.

## Редактор и история

Выбор объекта не меняет render result. Handle drag, ввод числа и arrow nudge дают одинаковую модель координат. Locked object не меняется интерактивной геометрической командой. Одна завершённая операция drag — один undo step; intermediate mouse events не наполняют историю сотнями команд. После undo новая правка удаляет redo branch.

Каждая команда имеет данные до/после, устойчивый object ID и атомарно применяется к документу. Undo создания удаляет объект и его ссылки; redo восстанавливает те же ID. Открытие проекта либо создаёт новую document history, либо восстанавливает сериализованную историю по явно заявленной политике. Наличие undo в памяти не означает сохранение всей истории между запусками.

Полноценная будущая группа не образует цикл. Reparent сохраняет визуальное положение либо явно предлагает выбранную политику transform. Общая opacity перемножается по иерархии. Текущая реализация групп ограничена меткой и общим переключением видимости. Порядок собственного UI явно подписан `back → front`: compositor обходит массив от фона к переднему плану. Это отличается от документированного сверху-вниз списка MadMapper. Удаление объекта, используемого Cue/track, должно создавать понятную missing-target запись и не менять другой объект с совпавшим именем.

## Композиция, маски и цвет

Базовый compositor объявляет color space и alpha convention. Для normal blending математический oracle использует `C = Cs*As + Cd*(1-As)` для непрозрачного destination; general alpha учитывается отдельно. Переход straight↔premultiplied выполняется один раз на границе decoder/texture, чтобы избежать тёмных ореолов.

G14: внутренняя маска умножает alpha только своей поверхности; standalone/global mask затрагивает только явно определённые нижние слои; групповая маска ограничена группой. Один и тот же path fill rule используется preview и output. G16: feather=0 даёт жёсткую границу; ненулевая ширина имеет монотонную alpha и определённые единицы canvas/UV. Изменение view zoom не меняет растушёвку.

G17: два комплементарных edge ramps проверяются на суммарную яркость до физического вывода. Gamma/power является явным параметром. Это не обещание невидимого шва для произвольных реальных проекторов: H требует модели, освещённости, overlap и измерения. Black-level compensation — отдельная возможность, если будет реализована.

## Группы и локальные системы координат

Schema 3 определяет UUID-группы с parentID, полной affine-матрицей, opacity и enabled. Поверхность с groupID хранит output/mesh в системе родителя. World transform — произведение матриц от корня; source input/mask не преобразуются. Перенос, ненулевой масштаб (включая отражение), поворот и возникающий shear сохраняются без декомпозиции. Положительный UI-угол — по часовой стрелке с учётом 16:9 canvas; scale/rotation вокруг мирового pivot, затем translation. Граница иерархии — 64 уровня/4096 групп; циклы, missing refs, нечисловые, сингулярные и выходящие за рабочие диапазоны состояния отклоняются атомарно.

Assign/reparent сохраняют мировую геометрию, но принимают наследуемые opacity/visibility нового родителя. Родительская opacity перемножается после surface automation; ancestor enabled соединяется AND с индивидуальными flags. Группа не меняет плоский порядок слоёв и не создаёт изолированный framebuffer. Для двух opaque red/blue слоёв в группе opacity 0.5 на чёрном ожидается около RGB `(64,0,128)`, а не whole-group fade.

Dissolve сохраняет current/cue геометрию и видимое состояние, передавая transform/opacity/enabled прямым потомкам, не удаляя поверхности/media. При non-unit group opacity и opacity track любого прямого current/cue target операция отклоняется, чтобы track не отменил запечённый множитель. Undo/Redo восстанавливает весь Project. Назначение тому же parent и identity transform — точный no-op.

Сцены остаются surface-only и ссылаются на текущие общие group definitions. При смене groupID в переходе parent и output/mesh дискретно переключаются в `t=0.5`; одинаковый parent допускает прежнюю геометрическую интерполяцию. Прерывание перехода редактированием фиксирует промежуточный state как dirty/undoable, даже без движения handle. Ошибка resolution закрывает вывод пустой композицией с диагностикой.

## Медиа и время

Медиавремя хранится независимо от UI timer. Monotonic clock определяет позицию во время play; pause фиксирует позицию. Seek применяется к выбранному media source, очищает устаревшие queued frames и имеет generation ID: поздний кадр предыдущего seek не может заменить новый. Интерфейс не ждёт decoding/network I/O.

Очередь декодированных кадров ограничена. При перегрузке renderer выбирает кадр с подходящим PTS и считает пропуски; UI показывает измерение вместо блокировки. Очереди и dropped-frame policy документируются в архитектуре. Нулевой duration и повреждённый stream не запускают бесконечный seek loop.

V03: pause удерживает тот же presentation frame; seek в pause обновляет кадр и остаётся в pause. Loop использует полуоткрытый диапазон `[in,out)`, если backend позволяет; достижение конца переводит в in с сохранением избыточного media time. Seek clamp, seek accuracy и поддерживаемые кодеки указываются по фактическому backend. При неизвестном duration UI не выдаёт ложную длину.

В первом проходе допустим один media clock и ограниченный набор codecs, если это явно указано в status. V04 reverse/ping-pong, V05 folder player, многоканальное аудио и синхронизация — отдельные требования, не выводимые из кнопки play.

Missing file не изменяет геометрию и назначения. UI показывает исходный относительный путь, предлагает relink, выводит определённый placeholder или black по выбранной политике. Ошибка decoder не завершает процесс. Live source disconnect освобождает устройство и оставляет понятный статус.

## Независимые outputs

Редактор и output — разные окна и render targets. Output не содержит toolbar, handles или file dialogs. Выбор дисплея явный; в одноэкранной среде возможна только функциональная проверка окна, а не подтверждение второго физического output. Escape/команда закрытия возвращает управление без потери проекта.

Каждый output имеет ID, назначение экрана, размер, route и enabled. Переподключение экрана не назначает его молча по изменившемуся индексу. При исчезновении экрана сохраняется routing и показывается unavailable. Preview использует тот же rendering path; наложения редактора проходят отдельным последним слоем.

Loopback читает завершённый render target. Циклическая зависимость запрещена либо имеет явный frame delay и лимит history buffers. Нельзя одновременно читать и писать одну и ту же texture без определённой синхронизации.

## Проекты, сохранение и восстановление

Формат собственный, с magic/application ID и целочисленной schema version. Устойчивые ID не зависят от имён. Ресурсы хранятся по относительным путям от project directory; абсолютный исходный путь может быть необязательным диагностическим hint. Разбор валидирует типы, размеры списков, конечность чисел и ссылки до замены открытого документа.

Сохранение пишет временный файл рядом с целевым, завершает запись и атомарно заменяет целевой. Ошибка не уничтожает последнюю корректную версию. Recovery snapshot отделён от ручного save. При запуске найденное более новое recovery предлагается восстановить; оно не открывается поверх другого проекта без явной привязки ID/path. Проверка восстановления обязана включать прерывание процесса.

Неизвестная будущая версия открывается только read-only или отклоняется; она не перезаписывается старой схемой. Миграции детерминированы и тестируются fixtures каждой поддерживаемой schema. Project collect копирует только явно используемые доступные ресурсы, разрешает коллизии имён, сохраняет относительные ссылки и сообщает missing resources. Не импортируются пользовательские MadMapper проекты без отдельной реализации и тестов.

## Шоу, автоматизация и синхронизация

S01 Scene — полный снимок заявленных полей; S02 Cue — набор `objectID/parameterID/value`. Cue не меняет остальные значения или media clock. Transport restart — отдельное действие. Переход непрерывных значений начинается с фактического текущего состояния; discrete fields переключаются по заявленному правилу, например в конце.

Timeline evaluation чистая функция времени для continuous tracks. Event tracks отдельно учитывают пересечение интервала; seek не пересылает все прошлые MIDI/OSC события без явной опции. Markers имеют bounded follow-action execution, чтобы циклический jump не зависал. Row/bank exclusivity и конфликтующие параметры разрешаются детерминированно. S09 календарь использует timezone; DST, reboot и repeated occurrences покрываются fake-clock tests.

Синхронный запуск по UDP не считается frame sync. Для N06 измеряются phase, drift, latency и восстановление после пропажи clock. Ableton Link, MIDI clock и timecode — независимые backends со своими capabilities.

## Протоколы и свет

Все packet parsers сначала проверяют длины, типы, диапазоны и padding; malformed input не частично меняет состояние. Network callbacks передают ограниченные сообщения в thread-safe queue, а модель меняется на владельце editor/show engine. Нельзя выполнять arbitrary shell/file operations по сетевому сообщению.

N02 OSC поддерживает только документированный набор типов и адресов. Unknown/mismatched value диагностируется и игнорируется. N04 Art-Net и N05 sACN имеют собственные тесты байтового порядка, длины, universe numbering, sequence wrap, timeout и termination. Успешный encoder test не означает UDP roundtrip, а UDP roundtrip не означает совместимость физического node.

L01 sampling выполняется из выходной композиции по отдельному render target. RGB→DMX преобразование имеет явную response curve и rounding. L02 patch хранит universe и channel с однозначной базой; fixture span через границу 512 либо разрешён и корректно разбит, либо отвергнут validation. Overlap не молча уничтожает другой прибор. L03 coarse/fine и RGBW extraction имеют численный oracle.

При отключённом реальном output simulator остаётся доступным и не отправляет broadcast самопроизвольно. Реальный световой вывод включается явной конфигурацией network interface и target. Blackout/termination policy должна быть описана для каждого protocol. L08 recorder использует открытый собственный формат; воспроизведение проверяется на идентичность channel bytes и timestamps.

## 3D, scanning и опциональные SDK

H01 OBJ parser имеет лимиты и проверяет indices; normals/UV/depth подтверждаются собственными простыми моделями. H02 calibration проверяется на синтетической камере с известными параметрами и на degeneracy/outliers. H03 structured-light pipeline получает кадры синтетической сцены, затем отдельно проходит физический стенд. Калибровочная карта не называется 3D reconstruction.

Каждый аппаратный adapter сообщает capability/version/driver/device state. Базовая сборка открывает проекты с отсутствующим adapter, сохраняя его настройки и показывая unavailable. SDK и binary redistribution не добавляются автоматически. Для NDI, vendor camera SDK, Spout/Syphon, USB-DMX, MiniMad и laser отдельные licensing и hardware reports обязательны перед заявлениями о совместимости.

## Отчёт о проверке и производительности

Для каждого build указывать commit, ОС, CPU/GPU/RAM, backend, разрешение, codec/pixel format, surface/output count, длительность теста, FPS и frame time percentiles, drops и память. CPU/GPU utilization публиковать только если измерены конкретным инструментом. 4K/60, неопределённое «unlimited» и полное равенство MadMapper не выводятся из архитектуры или производителя GPU.

Порядок приёмки: unit geometry/state/packets → deterministic frame comparisons → desktop launch/import/transport/save/reopen/undo → soak → физические outputs/devices. Для каждого непроверенного пункта сохраняется причина и ближайшая проверка; кнопки и документы не меняют статус функции на I.
